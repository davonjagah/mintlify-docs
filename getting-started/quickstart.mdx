This quickstart walks you through making your first Transika sandbox API call. You'll hit the beneficiary networks endpoint — a safe, read-only route that returns the supported mobile money and bank networks — so you can confirm your API key, environment URL, and response parsing work correctly before building any real product flows.

## Prerequisites

<Note>
  Before you make your first request, confirm you have the following:

  - An **approved merchant account** with KYB status `approved`
  - The **`api_access`** feature enabled on your merchant account
  - A **test API key** with at least the `api:read` or `api:write` scope

  Your full API key secret is shown **only once** at creation time. Copy it to your secret manager immediately — it cannot be retrieved later.
</Note>

## Make your first request

<Steps>
  <Step title="Export your API key as an environment variable">
    Store your test key in a shell variable so you never paste secrets directly into commands:

    ```bash
    export TRANSIKA_API_KEY="txk_test_REPLACE_ME"
    ```

    Replace `txk_test_REPLACE_ME` with the actual key you received when creating your sandbox API key.
  </Step>

  <Step title="Call the beneficiary networks endpoint">
    Run the following `curl` command against the sandbox base URL. This endpoint requires no request body and has no side effects:

    ```bash
    curl --request GET \
      --url "https://sbx-institutional.tran-sika.com/sandbox/v1/beneficiaries/networks?kind=momo" \
      --header "Authorization: Bearer ${TRANSIKA_API_KEY}" \
      --header "Accept: application/json"
    ```

    The `kind=momo` query parameter filters results to mobile money networks. You can omit it to retrieve all supported network types.
  </Step>

  <Step title="Parse the response">
    A successful request returns a JSON envelope like this:

    ```json
    {
      "status": "success",
      "message": "success",
      "data": {
        "networks": [
          { "code": "MTNGH", "label": "MTN Mobile Money", "kind": "momo" }
        ]
      }
    }
    ```

    Every Transika API response wraps its payload in the same top-level envelope:

    | Field | Description |
    | --- | --- |
    | `status` | `"success"` on a successful request, or an error indicator on failure |
    | `message` | A human-readable summary of the outcome |
    | `data` | The endpoint-specific payload — the shape of `data` varies per route |

    If your response shows `"status": "success"` and a populated `data.networks` array, your key, environment, and HTTP client are all configured correctly.
  </Step>
</Steps>
